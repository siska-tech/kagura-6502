# VDP と VRAM（RTL v1.0 RC）

対象は aud_p1024（1024 パターン、256 スプライト）です。波形ミキサーは [音源仕様](audio.md) を参照してください。

## 1. 画面

| 項目 | 値 |
|---|---|
| HDMI 出力 | 1280×720 / 60 Hz（CEA VIC 4）、ピクセルクロック 74.25 MHz、1 ライン 1650 クロック、1 フレーム 750 ライン（既存の `k65_hdmi_tx`、変更なし） |
| 論理出力 | 320×180（4×4 倍） |
| **有効描画領域** | **320×176** = 論理ライン 2〜177（HDMI ライン 8〜711） |
| ボーダー | 上: 論理ライン 0, 1（HDMI 0〜7）、下: 論理ライン 178, 179（HDMI 712〜719）。左右は無し |
| タイル | 8×8、**40 列 × 22 行**（320×180 では 22.5 行で半端が出ていた） |
| 色 | 4 bpp（16 色）× 16 パレット = 256 エントリ、RGB565 |
| 疑似ビットマップ | 全画面 40×22 = **880 パターン** |

**ボーダーは出力段で生成する。** パターン、マップ、OAM のどれも使わない。レンダラは各論理ラインのボーダー色（パレット 0 のインデックス）をラインバッファの未使用スロット（x = 320）に書き、出力段はボーダー行でその値をパレットの読み出しアドレスに使う。ボーダーのために追加した記憶素子は、レジスタ数個だけである。

### 1.1 座標系

| 対象 | 規則 | 320×180 との違い |
|---|---|---|
| 背景 | 画面 (x, sy)、sy = 0〜175 は世界座標 ((SCX + x) mod 512, (SCY + sy) mod 256) を表示。マップは 64×32 タイル（512×256 px）で両方向に折り返す | 縦の可視範囲が 180 → 176 行。マップとスクロールの仕様は同じ |
| スプライト | 画面 x = X − 16、画面 sy = Y − 16（X, Y は 9 ビット、0〜511） | Y の原点は**有効領域の上端**（ボーダーの下）。ボーダー行には描かない |
| クリッピング | x < 0、x ≥ 320、sy < 0、sy ≥ 176 の画素は描かない。左端と上端にはみ出せるよう、座標に 16 のバイアスを持たせた | 下端が 176 になった |
| ラスタタイミング | 論理 1 ライン = HDMI 4 ライン = 88.9 µs = **4,800 sysclk**（54 MHz）。ライン L を表示している間にライン L+1 を描く。ライン 0（上ボーダー）は垂直帰線の開始（HDMI ライン 720）に描く | 変更なし |

## 2. レジスタ（CPU の `$D300–$D33F`）

コアの外部 I/O 窓（`k65_basic_core` の `EXT_EN=2`）。ウェイト 0（PHI2 ストレッチなし）で、タイミングは `$D000–$D00F` と同じ。`$D340–$D3FF` は `$D300–$D33F` の写し。

| アドレス | 名前 | R/W | 内容 |
|---|---|---|---|
| `$D300` | VADDR0 | R/W | VRAM アドレス bit 7..0 |
| `$D301` | VADDR1 | R/W | bit 15..8 |
| `$D302` | VADDR2 | R/W | bit 16。**書くと、そのアドレスから先読みを始める** |
| `$D303` | VDATA | R/W | VRAM データ。書き込み・読み出しのたびにアドレス += VINC。読み出しは先読み済みの値を返し、次を先読みする |
| `$D304` | VINC | R/W | アドレスの増分（初期値 1） |
| `$D305` | CTRL | R/W | b0 背景表示、b1 スプライト表示、b7 VBLANK 割込み許可（初期値 `$03`） |
| `$D306` | STATUS | R | b7 VBLANK（フレームの開始＝HDMI ライン 720 で 1、**読むと 0**）、b6 スプライト溢れ（前のフレームで 1 ラインに 65 個以上。読むと 0）、b0 描画中 |
| `$D307` | **BORDER** | R/W | §3 |
| `$D308` / `$D309` | SCX | R/W | 横スクロール 9 ビット（`$D309` は bit 0 だけ） |
| `$D30A` | SCY | R/W | 縦スクロール 8 ビット |
| `$D30B` | LINE | R | 描画中（または最後に描いた）論理ライン 0〜179 |
| `$D30C` / `$D30D` | PATCNT | R | 実装されたパターン数（ビルドで決まる。例: 1024 = `$00`, `$04`） |
| `$D310–$D312` | CH0_INC | R/W | 波形 ch0 の位相増分 24 ビット（48 kHz ごとに加算、上位 8 ビットがサンプル番号） |
| `$D313` | CH0_VOL | R/W | b7..4 左、b3..0 右 |
| `$D314–$D317` | CH1_INC / CH1_VOL | R/W | ch1（同じ形式） |
| `$D318` | ACTRL | R/W | b0 ch0 有効、b1 ch1 有効 |

**アクセス間隔:** VRAM の 1 操作は最大 7 sysclk かかる。VDATA と VADDR2 への連続アクセスは 8 sysclk 以上空けること。W65C02S が 6.75 MHz 以下（CYC ≥ 8）なら、命令の並びに関係なく満たす（3.375 MHz では 1 サイクルが 16 sysclk）。
**IRQ:** CTRL b7 = 1 のとき、VBLANK フラグが立っている間 IRQB を Low にする（STATUS を読むと解除）。`$D000` の b6 で VDP の IRQ を判別できる。

## 3. ボーダー制御レジスタ（`$D307` BORDER）

| ビット | 名前 | 内容 |
|---|---|---|
| 3..0 | COLOR | **パレット 0** のインデックス 0〜15。初期パレット（§4.4）は ZX Spectrum と同じ並び: 0 黒、1 青、2 赤、3 マゼンタ、4 緑、5 シアン、6 黄、7 白、8〜15 はその明るい色 |
| 6..4 | — | 予約（0 を書く） |
| 7 | MODE | 0 = **フレーム単位**（初期値）: 垂直帰線の開始で取り込み、次のフレームの全ボーダーに使う。1 = **ライン単位**: 各論理ラインを描く時点の値を使う（将来のラスタ効果用） |

- リセット値は `$00`（黒、フレーム単位）。BIOS（VDP 版）も起動時に 0 を書く。
- ボーダーの色は、そのフレームのパレット 0 の内容で決まる。パレット 0 の 0〜15 番を書き換えると、ボーダーの色も変わる。
- **ライン単位への拡張性:** ボーダー値は論理ラインごとにラインバッファへ書かれるので、MODE=1 では、CPU がライン割込み（将来）や `LINE` レジスタのポーリングで書き換えた値が、その次に描くラインから反映される。出力段の変更は要らない。現在は、ボーダーがあるのは上下の 4 論理ラインだけなので、MODE=1 の効果は「上下の帯の途中で色が変わる」ことに限られる。
- 将来の BASIC: `BORDER n` は `POKE 54023, n AND 15` と同じ動作にする。

## 4. VRAM（CPU から見た 17 ビットアドレス、VADDR / VDATA 経由）

| 範囲 | 内容 | 実体 |
|---|---|---|
| `$00000–$07FFF` | パターン: 1 枚 32 バイト（8 行 × 4 バイト）。**PATCNT 以上の番号は、書き込みを捨て、読むと 0（表示では透明）** | 512×32 の SP ブロック × ceil(PATCNT/64) |
| `$08000–$08FFF` | マップ 64×32 エントリ、各 2 バイト（下位、上位） | SP 2048×8 × 2 |
| `$09000–$097FF` | OAM 256 スプライト × 8 バイト | SP 512×32 × 1 |
| `$09800–$099FF` | パレット 256 × RGB565（下位、上位）。**書き込み専用**（読むと 0） | パレット / 波形の共有 SDPB |
| `$09A00–$09AFF` / `$09B00–$09BFF` | 波形 ch0 / ch1、各 256 サンプル（符号付き 8 ビット）。書き込み専用 | 同上 |

パレットと波形は 16 ビット単位で書く: 偶数アドレスの値を保持し、奇数アドレスを書いた時点で 16 ビットを書き込む（自動インクリメントで連続して書けば、そのとおりになる）。

### 4.1 パターン
行 r（0〜7）の 4 バイト = 画素 0..7、各バイトの上位 4 ビットが左の画素。色 0 は透明（背景では背景色＝パレットエントリ 0）。

### 4.2 マップエントリ
下位バイト = パターン番号 bit 7..0。上位バイト = {パレット[3:0], 縦反転, 横反転, パターン番号 bit 9..8}。

### 4.3 OAM エントリ（8 バイト）
| バイト | 内容 |
|---|---|
| 0 | Y bit 7..0 |
| 1 | b7 有効、b6 16×16（0 = 8×8）、b0 Y bit 8 |
| 2 | X bit 7..0 |
| 3 | b0 X bit 8 |
| 4 | パターン bit 7..0 |
| 5 | b5 縦反転、b4 横反転、b1..0 パターン bit 9..8 |
| 6 | b3..0 パレット |
| 7 | 予約 |

16×16 は 4 枚のパターン p, p+1（上段左右）、p+2, p+3（下段左右）。反転は 16×16 全体に対してかかる。

### 4.4 パレットの初期値
エントリ 0〜15（パレット 0）は ZX Spectrum の 16 色（通常 = 0xD7、明るい = 0xFF）、それ以外は 0（[vdp_palette.hex](../fpga/vdp/rtl/vdp_palette.hex)）。マップ、OAM、パターンは FPGA のコンフィギュレーションでは初期化されない（BSRAM の初期値を持たせていない）。**VDP 版の BIOS が起動時にマップ、OAM、パターン 0 を 0 にする**（約 16 ms）。

## 5. 描画

| 項目 | 内容 |
|---|---|
| 優先順位 | スプライト（番号が小さいほど上）＞ 背景 ＞ 背景色（パレットエントリ 0） |
| 1 ラインのスプライト | 256 個を走査し、番号の小さい順に最大 **64 個**。超えた分は表示しない（STATUS b6） |
| 処理時間（Sim で計測） | 通常 1,034〜1,902 sysclk、最悪（256 個すべて 16×16 が同じ行 ＋ CPU が全速で VRAM に書き込み）**2,846 sysclk**。予算 4,800（59 %）。超過（オーバーラン）は全試験で 0 |
| CPU とレンダラの調停 | VRAM（SP ブロック）の 1 ポートを共有。CPU の操作中（最大 7 sysclk）はレンダラが待つ。OAM はシャドウを持たない（§6 の D） |
| 出力段 | 先読み 5 クロックのパイプライン: ラインバッファ → パレット → rgb（2 段）。`k65_hdmi_tx` の契約「rgb は (cx, cy) から 1 クロックで登録」を満たす |
| パレットと波形の共有 | パレットの読み出しは論理 1 画素（4 ピクセルクロック）に 1 回。残りの 3 回で波形を読む（48 kHz × 2 ch） |
